## Verdict

The load-bearing parts are sound (custody mapper, server-owned identity, encrypted release, D1 concurrency, read-only panel). What weighs the product down is mass: dead CSS and dead components, a V2 seam that wraps V1, guardrail tests that pin both, and root docs that tell agents to keep forking. Three product-rule defects are open and go first — the client infers 'Listed online' from an English label, loaner alert text reaches transport roles, and a stock-number-only 'delivered' row hides a still-listed vehicle — and gap research found a fourth: every tab's first refresh discards the open vehicle's private evidence because the ETag entry is thrown away on first load. **The biggest lever is to delete before building**, then install two gates so the mass cannot regrow, and only then consolidate CSS, rows and destinations.

## Principles

1. Delete before you add; superseded files, rules and tests leave in the same PR. No `*-final`, `*-polish`, `*-vN`, `.flow`, `V2` filenames.
2. One owner per fact: status codes come from the server; labels are display-only; one token file, one button, one scope switch, one status vocabulary, one search-text builder.
3. Sources stay read-only evidence; the client never infers one status family from another's text; 'No current DealerMail hold found' is never rendered or filtered as available.
4. Gates only ratchet: visual baseline (zero counted pixels), design ratchet, write-surface, ETag/304 and role-matrix canary tests run in CI; raising a baseline needs `--accept` and a commit message saying why the old output was wrong.
5. Ship in slices that stay green: one or two PRs per move, `pnpm check` plus screenshots at 390/1024/1320/1440 from `pnpm dev:demo`, measured before/after in the PR.
6. No new runtime layers: no fetch/cache/state library, no virtualization while paginated, no client persistence of the bootstrap, no framework in the panel, no new write routes.
7. Rules live in AGENTS.md (imported by CLAUDE.md); everything else links to it.
